# RKIC Website — Reminder Instructions (Standing Rules)

Yeh document un saari standing instructions/reminders ki list hai jo maine is RKIC product catalog website (github.com/rkic1976-bot/RKIC-SITE, live rkic1976-bot.github.io/RKIC-SITE/, canonical URL rkic1976-bot.github.io/RKIC-SITE (no custom domain yet, decide later)) ko banate waqt apne paas note kar rakhi hain — jab bhi website par kaam start karta hoon, in sab rules ko follow karta hoon. Aapne repeated mistakes ki wajah se yeh compile karne ko kaha, isliye is baar sab ek jagah, transparently likh raha hoon.

## 1. Communication — kaise respond karna hai

## 2. Har naya product add karne ka workflow (step-by-step)

1. Aap product ki photo + brand/subcategory bhejte hain.
2. Main pehle check karta hoon ki yeh kahin already-added product ki duplicate photo to nahi (perceptual/pixel hash compare existing images/*.jpg ke against) — agar similar lage to pehle poochta hoon, guess nahi karta.
3. Nameplate/label par likha hua text hamesha authoritative hai — agar aapne jo naam bataya aur nameplate par likha mismatch ho, to main aage badhne se pehle clarify karta hoon (guess karke galat product nahi bana deta).
4. Official sources se specs research karta hoon.
5. Image processing: 600px thumbnail + 1100px large, dono base64 data-URI embed, JPEG quality 90–92% (kabhi 55% nahi), LANCZOS resize, white canvas par center karke. Background whitening brightness+saturation-gated hoti hai (ek global threshold nahi) taaki nameplate/label ka text safe rahe.
6. Standalone SEO-optimized product HTML page banata hoon (existing similar template se, ya fresh agar spec fields alag hain).
7. `index.html` (products array + subcategoryMap agar naya subcategory hai), `sitemap.xml`, `brand-data.js` sab update karta hoon.
8. `products-added-list.md` mein detailed entry likhta hoon — taaki duplicate na ho aur history track rahe.
9. Sandbox repo (`/tmp/rkic/RKIC-SITE`) mein locally commit karta hoon — **GitHub par push NAHI karta** (yeh explicit instruction hai). Aap files/zip dekh kar review karte hain; poora batch-upload baad mein ek saath hoga jab poora catalog complete ho jaayega.
10. Aapko changed/naye files deliver karta hoon.

## 3. Naya seekha gaya rule (is session ki galti se) — **standalone page delivery**

Yeh code ka bug nahi hai, sirf delivery format ka issue hai — lekin isse repeatedly bachne ke liye ab se **standalone page ke saath hamesha `brand-data.js` (zip mein) dena hai**, chhote se chhota edit ho tab bhi.

Yaani har naye/edited product page delivery mein do cheezein jaani chahiye: (1) `.html` page akele, standalone file ke roop mein, aur (2) zip (page + `brand-data.js`) poori functionality ke liye. ## 4. Site-wide technical conventions (permanent, sab current/future products par apply)

- **Image quality**: hamesha 90–92% JPEG (kabhi 55% nahi) — thumbnail aur large dono.
- **Lightbox zoom**: `data-large` attribute hamesha main image (`src`) ke barabar hona chahiye.
- **Cofi brand**: Manufacturer hamesha "Cofi srl" (kabhi "Cofi Ignitions" nahi).
- **Honeywell brand**: koi bhi location/place name (jaise Golden Valley MN) na likhein — sirf "Honeywell".
- **Vanaz brand**: har product mein "Manufacturer: Vanaz Engineers Ltd, Pune" row zaroori hai.
- **Siltek brand**: aapka apna in-house brand — hamesha R.K. Instruments & Controls logo dikhana hai (text tag nahi), naya logo kabhi mat banao.
- **R.K. Instruments & Controls umbrella brand**: jab brand field yeh ho, existing RKIC logo reuse karna hai, aur actual manufacturer ka naam "Manufacturer" field mein. Exception: kuch products (jaise SRG-21, SP 2307) mein aap khud hi actual manufacturer ho — un par Brand aur Manufacturer dono "R.K. Instruments & Controls" hote hain.
- **Gas meters**: spec label hamesha "Size and Capacity" (kabhi "Meter Size" nahi); part number label hamesha "Part No." (kabhi "Order No." nahi); Connection Size Honeywell Elster BK-G MWA chart se (G4=1", G6=1", G10=1¼", G16=2", G25=2", G40=2½", G65=3", G100=4").
- **Pressure switches**: "Adjustable Setting Range" spec row compulsory hai (Maximum Pressure se alag) — agar pata nahi to guess nahi karna, aapse poochna hai.
- **Ignition Electrodes**: har product mein "Electrode & Wiring Material: Kanthal A1 (FeCrAl resistance wire)" row compulsory hai.
- **Brand stock-count badges** ("26 added" jaise): hamesha visible rakhne hain jab tak aap catalog ko explicitly "final" declare na karein.
- Do models jinke specs almost same hon, sirf size/connection alag ho — unke liye ek hi combined page banani hai, alag-alag nahi (jaise QA40 DN25 vs DN40).
- **Koi bhi mandatory/critical spec (Supply Voltage, Power Consumption, Adjustable Setting Range, Box Size/Cut-Out, waghera) agar photo ya diye gaye text mein clearly nahi mila** — kabhi guess ya kisi similar sibling product se copy nahi karna — seedha aapse poochna hai (zaroor par AskUserQuestion se options de sakta hoon, lekin exact figure aapke text se hi aayega).
- **Wiring/Terminal Guide tables mein Earthing terminal**: jahan bhi Earthing/Ground terminal row ho, uska function-description ke saath yeh bhi explicitly mention karna hai ki yeh **compulsory connection for safe operation** hai (bold emphasis ke saath) — sirf function bata dena kaafi nahi.
- **Sequence/Wiring jaisे custom sections wale products ke liye**: agar kisi product page par generic spec-table se aage koi custom hand-written section ho (jaise SP 2307 ka "Sequence of Operation" ya "Wiring & Terminal Guide"), to woh section sirf standalone page tak simit nahi rehna chahiye — `index.html` ke single-product view (`#/product/...`) mein bhi wahi content mandatory dikhna chahiye, taaki catalog se dekhne wale ko bhi "full specifications" mile. Site pattern: product object mein optional `extraHTML` field (standalone page jaisa hi hand-written HTML), aur `productCardHTML(p, showExtra)` ismein sirf single-product detail view mein render karta hai (category/brand listing views mein nahi, taaki wahan clutter na ho).
