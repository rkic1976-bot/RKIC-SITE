# RKIC Website — Reminder Instructions (Standing Rules)

Yeh document un saari standing instructions/reminders ki list hai jo maine is RKIC product catalog website (github.com/rkic1976-bot/RKIC-SITE, live rkic1976-bot.github.io/RKIC-SITE/, canonical domain rkinstruments.in) ko banate waqt apne paas note kar rakhi hain — jab bhi website par kaam start karta hoon, in sab rules ko follow karta hoon. Aapne repeated mistakes ki wajah se yeh compile karne ko kaha, isliye is baar sab ek jagah, transparently likh raha hoon.

## 1. Communication — kaise respond karna hai

- Hamesha Hindi mein respond karna hai (aapki explicit standing instruction hai, sirf casual baat-cheet mein nahi — har response mein).
- Style: direct aur terse rakhna — lamba-chauda explanation nahi, seedha kaam ki baat.

## 2. Har naya product add karne ka workflow (step-by-step)

1. Aap product ki photo + brand/subcategory bhejte hain.
2. Main pehle check karta hoon ki yeh kahin already-added product ki duplicate photo to nahi (perceptual/pixel hash compare existing images/*.jpg ke against) — agar similar lage to pehle poochta hoon, guess nahi karta.
3. Nameplate/label par likha hua text hamesha authoritative hai — agar aapne jo naam bataya aur nameplate par likha mismatch ho, to main aage badhne se pehle clarify karta hoon (guess karke galat product nahi bana deta).
4. Official sources se specs research karta hoon.
5. Image processing: 600px thumbnail + 1100px large, dono base64 data-URI embed, JPEG quality 90–92% (kabhi 55% nahi), LANCZOS resize, white canvas par center karke. Background whitening brightness+saturation-gated hoti hai (ek global threshold nahi) taaki nameplate/label ka text safe rahe.
6. Standalone SEO-optimized product HTML page banata hoon (existing similar template se, ya fresh agar spec fields alag hain).
7. `index.html` (products array + subcategoryMap agar naya subcategory hai), `sitemap.xml`, `brand-data.js` sab update karta hoon.
8. `products-added-list.md` mein detailed entry likhta hoon — taaki duplicate na ho aur history track rahe.
9. Sandbox repo (`/tmp/rkic/RKIC-SITE`) mein locally commit karta hoon — **GitHub par push NAHI karta** (yeh explicit instruction hai). Aap files/zip dekh kar review karte hain; poora batch-upload baad mein ek saath hoga jab poora catalog complete ho jaayega.
10. Aapko changed/naye files deliver karta hoon.

## 3. Naya seekha gaya rule (is session ki galti se) — **standalone page delivery**

Yeh code ka bug nahi hai, sirf delivery format ka issue hai — lekin isse repeatedly bachne ke liye ab se **standalone page ke saath hamesha `brand-data.js` (zip mein) dena hai**, chhote se chhota edit ho tab bhi.

Yaani har naye/edited product page delivery mein do cheezein jaani chahiye: (1) `.html` page akele, standalone file ke roop mein, aur (2) zip (page + `brand-data.js`) poori functionality ke liye. ## 4. Site-wide technical conventions (permanent, sab current/future products par apply)

- **Image quality**: hamesha 90–92% JPEG (kabhi 55% nahi) — thumbnail aur large dono.
- **Lightbox zoom**: `data-large` attribute hamesha main image (`src`) ke barabar hona chahiye.
- **Cofi brand**: Manufacturer hamesha "Cofi srl" (kabhi "Cofi Ignitions" nahi).
- **Honeywell brand**: koi bhi location/place name (jaise Golden Valley MN) na likhein — sirf "Honeywell".
- **Vanaz brand**: har product mein "Manufacturer: Vanaz Engineers Ltd, Pune" row zaroori hai.
- **Siltek brand**: aapka apna in-house brand — hamesha R.K. Instruments & Controls logo dikhana hai (text tag nahi), naya logo kabhi mat banao.
- **R.K. Instruments & Controls umbrella brand**: jab brand field yeh ho, existing RKIC logo reuse karna hai, aur actual manufacturer ka naam "Manufacturer" field mein. Exception: kuch products (jaise SRG-21, SP 2307) mein aap khud hi actual manufacturer ho — un par Brand aur Manufacturer dono "R.K. Instruments & Controls" hote hain.
- **Gas meters**: spec label hamesha "Size and Capacity" (kabhi "Meter Size" nahi); part number label hamesha "Part No." (kabhi "Order No." nahi); Connection Size Honeywell Elster BK-G MWA chart se (G4=1", G6=1", G10=1¼", G16=2", G25=2", G40=2½", G65=3", G100=4").
- **Pressure switches**: "Adjustable Setting Range" spec row compulsory hai (Maximum Pressure se alag) — agar pata nahi to guess nahi karna, aapse poochna hai.
- **Ignition Electrodes**: har product mein "Electrode & Wiring Material: Kanthal A1 (FeCrAl resistance wire)" row compulsory hai.
- **Brand stock-count badges** ("26 added" jaise): hamesha visible rakhne hain jab tak aap catalog ko explicitly "final" declare na karein.
- Do models jinke specs almost same hon, sirf size/connection alag ho — unke liye ek hi combined page banani hai, alag-alag nahi (jaise QA40 DN25 vs DN40).
- **Koi bhi mandatory/critical spec (Supply Voltage, Power Consumption, Adjustable Setting Range, Box Size/Cut-Out, waghera) agar photo ya diye gaye text mein clearly nahi mila** — kabhi guess ya kisi similar sibling product se copy nahi karna — seedha aapse poochna hai (zaroor par AskUserQuestion se options de sakta hoon, lekin exact figure aapke text se hi aayega).
- **Wiring/Terminal Guide tables mein Earthing terminal**: jahan bhi Earthing/Ground terminal row ho, uska function-description ke saath yeh bhi explicitly mention karna hai ki yeh **compulsory connection for safe operation** hai (bold emphasis ke saath) — sirf function bata dena kaafi nahi.
- **Sequence/Wiring jaisे custom sections wale products ke liye**: agar kisi product page par generic spec-table se aage koi custom hand-written section ho (jaise SP 2307 ka "Sequence of Operation" ya "Wiring & Terminal Guide"), to woh section sirf standalone page tak simit nahi rehna chahiye — `index.html` ke single-product view (`#/product/...`) mein bhi wahi content mandatory dikhna chahiye, taaki catalog se dekhne wale ko bhi "full specifications" mile. Site pattern: product object mein optional `extraHTML` field (standalone page jaisa hi hand-written HTML), aur `productCardHTML(p, showExtra)` ismein sirf single-product detail view mein render karta hai (category/brand listing views mein nahi, taaki wahan clutter na ho).

## 9. SEO & GEO — standing checklist (permanent, 8 Sep 2026 se)

Rahul ji ne Semrush ka "SEO vs GEO" diagram share kiya aur site ko us hisaab se check/fix karne ko kaha. Ye ab permanent standard hai — har naye product/page ke saath (aur periodically poore site ke liye) yeh sab maintain karna hai:

**Traditional SEO (existing routine, continue karna hai):**
- Har product page par unique meta title, meta description, meta keywords, canonical URL.
- og:title/description/image aur twitter:title/description/image tags.
- `sitemap.xml` mein har product ka `<url>` entry, `<lastmod>` current date ke saath.
- Page speed / Core Web Vitals — **image kabhi base64 inline mein embed nahi karni `index.html` ke `products` array mein** (ye ek baar 15.4MB tak pahunch gaya tha, 1.2MB par fix kiya 8 Sep 2026 ko). Naya rule: `image` field hamesha `images/{id}-large.jpg` (external file path) hona chahiye, `imageLarge` field hamesha `images/{id}-xl.jpg` — dono physical `.jpg` files ke roop mein `images/` folder mein save karni hain, JS array mein sirf path reference. **Standalone `products/{id}.html` pages ke liye is se ULTA rule hai — inme image HAMESHA base64 hi embed karni hai, external file path kabhi nahi.** (8 Sep 2026 ko galti se ek naye product, Dungs VPS 504 S04, ki standalone page mein external `../images/...` path use kar diya tha — jab file akele (zip/preview ke bina) kholi to image dikhi hi nahi, kyunki relative path standalone context mein resolve nahi hota. Turant base64 embed mein revert kiya.) Standalone pages ka base64 approach jaan-boojh kar hai — isse woh self-contained rehte hain aur akele deliver/preview karne par bhi sahi dikhte hain, chahe file size thodi badi ho jaye (kam critical hai, kyunki ek time par ek hi page load hota hai).

**Teesra rule (naya, 8 Sep 2026 ko is baar ek real bug se seekha) — shared data files (`brand-data.js`, `related-products-data.js`) mein bhi image kabhi base64 nahi honi chahiye, external file path hi.** Yeh do files har ek standalone product page (`products/*.html`, sab 127+) `<script src>` se load karti hain — pehle inme saare brands ke logos (`brand-data.js`) aur saare products ke 140px thumbnails (`related-products-data.js`) base64-embedded the, jisse dono files 570KB aur 600KB tak pahunch gayi thi. Rahul ji ne report kiya ki photo enlarge (zoom) karte waqt site **hamesha, sabhi jagah, sab browsers mein hang ho rahi thi** — root-cause: har standalone page ~1.17MB extra base64 (sirf in do shared files se) DOM mein already baitha hota tha, aur zoom ka full-screen lightbox overlay khulte hi browser ko poore heavy page ko recomposite karna padta tha, jisse stall/freeze hota tha. Maine ise live site par (real browser se) reproduce kiya — zoom click ke baad screenshot request 5+ second tak "page did not finish rendering" timeout hui. **Fix**: dono files ke logos/thumbnails ko physical files mein nikaal diya (`images/brands/brand-{slug}.png`, `images/thumbs/{id}-thumb.jpg`), JS mein sirf path reference (path `../images/...` se shuru hota hai kyunki yeh files sirf `products/` folder ke andar se load hoti hain) — `brand-data.js` 570KB→~2KB, `related-products-data.js` 600KB→~30KB. **Is se `index.html` affected NAHI tha** — usme apna khud ka chhota hardcoded `brandLogos` object hai aur related products SPA ke apne `products` array se compute hote hain, yeh do files load hi nahi karta. **Yaad rakhna**: koi bhi JS/data file jo MULTIPLE pages par shared/loaded hoti hai, usme image base64 embed karna standalone-page-jaisa "self-contained" fayda nahi deta — ulta, har page par woh bojh baar-baar load hota hai. Sirf ek page ke liye specific file (standalone product page khud) hi base64 se fayda leti hai; koi bhi shared/multi-page file hamesha external path use kare.

**Essential for both SEO + GEO (existing routine, continue karna hai):**
- JSON-LD structured data — har product page par `Product` schema + `BreadcrumbList` schema (dono `json.loads()`/valid JSON check ke saath verify karna).
- Homepage par `LocalBusiness` schema (address, phone, hours) — E-E-A-T/trust signal.
- Clear category → subcategory → product structure (topic authority).
- `products-added-list.md` changelog — content freshness signal (har addition/edit ka date-stamped record).

**GEO-specific (naya, 8 Sep 2026 se add):**
- **`llms.txt`** (repo root) — AI crawlers (ChatGPT, Perplexity, etc.) ke liye company summary, product categories, brands list, aur "notes for AI assistants" (jaise: part codes hamesha manufacturer label se verify karo, RKIC live pricing publish nahi karta — contact karo). **Jab bhi koi naya category ya naya brand add ho, `llms.txt` bhi update karna hai** (jaise `sitemap.xml`/`brand-data.js` ke saath hota hai).
- `robots.txt` mein sitemap link already hai — maintain karna hai.

**Verification pattern jo follow kiya (future audits ke liye reuse karna)**: `index.html` mein kitna % base64 image data hai check karne ke liye — `re.findall(r'data:image/[a-zA-Z]+;base64,[A-Za-z0-9+/=]{200,}', content)` se total base64 chars count karo aur file size se compare karo. Agar image data 50%+ ho, external-file conversion zaroori hai.
